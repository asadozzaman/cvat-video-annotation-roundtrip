Architecture / six steps

From MP4 to verified XML.

The principal workflow runs through Python and CVAT’s REST-backed SDK. CVAT’s browser interface is only a way to inspect the resulting task.

Execution path

Each boundary is checked before moving on.

Task creation, background processing, annotation storage, export, and import are separate operations with observable results.

01 / GENERATE

Numbered source video

OpenCV encodes a 60-frame MP4 and reopens the finished file to verify FPS, count, and dimensions.

synthetic_tracking.mp4
02 / CREATE

Task, label, media

CVAT receives the MP4 and a test_object label. The script waits for ingestion and reads the job and frame metadata.

POST /api/tasks · /data/
03 / ANNOTATE

One video track

Frames 5–20 carry explicit rectangle shapes; frame 21 ends the track with an outside flag.

PUT /api/tasks/{id}/annotations/
04 / EXPORT

Server-generated XML

The source task exports CVAT for video 1.1. Python parses its frames, coordinates, labels, keyframes, and outside flag.

POST /api/tasks/{id}/dataset/export
05 / IMPORT

New, clean task

The same video is attached to a second task. The exact CVAT archive is imported using the server’s CVAT 1.1 importer.

POST /api/tasks/{id}/annotations/
06 / VALIDATE

Read, compare, inspect

Live API annotations, both CVAT exports, and served frame images are checked against the expected video geometry.

Annotation model

Simple enough to audit frame by frame.

The orange object moves four pixels right on each source frame. Its rectangle is recorded explicitly on every visible frame, so alignment checks do not depend on interpolation.

  • Label: test_object
  • Visible: source frames 5 through 20
  • Outside boundary: frame 21
  • CVAT XML reports every shape as a keyframe

Asynchronous operations

The server decides when work is done.

Media ingestion, export, and import return background request IDs. Python polls their status and stops with a clear error if a request fails or exceeds 600 seconds.
